# 端到端驾驶学习路线

端到端不是只把很多模块塞进一个网络，而是让最终任务的监督信号贯穿学习链路。这个仓库采用逐步增加难度的方式，避免一开始就被大型数据集、CARLA 和 GPU 环境挡住。

## 第一阶段：状态到控制

运行 [`projects/end_to_end_driving/01_state_to_control`](../projects/end_to_end_driving/01_state_to_control)。专家控制器覆盖不同横向偏差、航向、速度和道路曲率，产生状态与动作对；神经策略用行为克隆学习转向和加速度。训练完成后，策略在从未见过的连续道路曲率上闭环运行。

这一阶段应理解：

- 行为克隆本质是监督学习，但部署时模型会遇到自己动作导致的新状态。
- 开环均方误差很低，不保证车辆在闭环中不会逐渐偏离。
- 训练数据的覆盖范围决定策略能从多大的扰动中恢复。
- 专家控制器是基线，也是数据和标签的来源，必须单独保留评测结果。

## 第二阶段：图像到控制

运行 [`02_image_to_control`](../projects/end_to_end_driving/02_image_to_control)。二维道路渲染器生成第一视角图片，CNN 把图片和车速直接映射为方向与加速度。使用与第一阶段相同的闭环仿真，比较视觉输入带来的误差。

## 第三阶段：图像到轨迹

运行 [`03_image_to_waypoints`](../projects/end_to_end_driving/03_image_to_waypoints)。模型预测一组未来轨迹点，确定性控制器将轨迹转换为车辆控制。中间轨迹提供可视化和约束接口，适合加入可行驶区域、碰撞检查和紧急制动。

## 第四阶段：接入真实工程

[`04_external_data`](../projects/end_to_end_driving/04_external_data/README.md) 定义 CARLA 或真实 ROS2 bag 转换后的统一数据契约。真实接入还需根据具体版本实现数据导出，并补齐模型导出、推理延迟、回放与安全兜底。理论背景继续阅读 [`awesome_hub` 的端到端章节](https://github.com/frankwang98/awesome_hub/blob/main/docs/autonomous-driving/end-to-end.md)。

## 评测原则

| 层级 | 指标 | 回答的问题 |
| --- | --- | --- |
| 开环 | 动作 MSE、轨迹 ADE/FDE | 模型能否复现数据中的专家 |
| 闭环 | 完成率、越界率、碰撞率 | 模型控制车辆后是否稳定 |
| 泛化 | 新道路、天气、噪声、初始扰动 | 数据分布变化时是否可靠 |
| 工程 | P50/P95 延迟、模型大小、资源占用 | 能否在目标硬件实时运行 |

所有项目都应记录随机种子、数据生成方式、训练配置、专家基线和失败案例。只展示一次成功轨迹不足以证明策略有效。
